## 2. 定案：九步（编号连续；⑥A/⑥B 是同一步的两个并行分支，不单独计步）

```
① 预注册：候选 + 指标契约 + 决策表 + 共享测量代码（只写一份，过黄金样例）
② 设计审 ───────────────────── 判定测法不公平 → 回 ①
③ 并行派 N 个 L1 写原型（spike，独立工作区）
④ 原型快审（跨家族，fail 不阻断）
⑤ 真跑 → runs/<日期>-<slug>-<候选名>/
   └─ 全部失败 / 差距小于噪声 → 按 ① 的决策表：停止，或回 ①/③
⑥ 互盲分析（两分支并行）
   ⑥A Codex sol ultra：证据账本 → 方案集 → 条件化判断
   ⑥B Claude 全新上下文：独立实验证据审阅（advisory，只读）
   └─ 任一分支提出含未测关键机制的方案 → 回 ③–⑤
⑦ L0 亲自核原始数据 → 对照两份互盲报告形成分歧清单 → 选 / 合成 → 写 spec/plan
⑧ Plan-Gate：Codex sol ultra 审 L0 的 spec/plan，喂全部数据 + 逐条回应分歧清单
⑨ 生产化：六步协议（见下）→ PR-GATE
```

> **编号口径唯一**：九个主步骤，不留空缺步号，不使用「十步」这一说法。
> （v2 曾同时出现「十步」「九个编号」「⑥B 子步」三种口径 —— r3 ②-1 指出。）

### ① 列候选 + 指标契约 + 决策表 + 共享测量代码

- ≥2 个**关键机制有实质差异**的候选（改名/改参数/明显更差的陪跑项不算）
- 指标契约含**列名 + 口径 + 噪声口径**（多种子 / 置信区间）+ **主指标 + 硬约束 + 平局处置**
- **决策表**：在看到结果前写死「什么结果区间 → 触发什么动作」，至少两个会导致不同动作的区间
- **实证回归容差的公式在此冻结**（r4 ③-2）：⑨ 的回归容差**不得到 ⑨ 才首次决定**——
  那时赢家表现已经看完，可以倒推一个容易通过的数。做法：**① 冻结计算公式**
  （如「不劣于赢家原型均值减 1 倍种子间标准差」），若数值须由 ⑤ 的噪声估计得出，
  则**数值写进 ⑦ 的 spec 并经 ⑧ 审查**，⑨ 只负责执行、不负责设定
- **测量代码只写一份**，候选只实现被测接口；**须先用已知结果的黄金样例跑一遍**
  —— 共享代码保证各候选**算法一致**；黄金样例**能发现部分系统性错误，提供一次非生成式检查**。
  ⚠️ **不得写成「黄金样例解决/证明了正确性」**：样例与测量代码可能一起错（§3 已列为治不了的一类）
- 冻结并记录：测量代码 hash、数据划分、种子、环境版本

### ② 设计审（advisory，fail 不阻断）

- 两问：① 有没有该试而没列进来的方案？② 这套指标与测法能否公平分出高下？
- 默认 `gpt-5.6-luna max` + `-s read-only`；测量代码为本次新写则升 `gpt-5.6-sol xhigh`
- **模型审查是 advisory；测量代码另有黄金样例这道非生成式检查**（两者都不是正确性证明）
- **判定测法不公平 → 回 ①**

### ③ 并行派 N 个 L1（原型 = spike）

> **⚠️ 本步是 `[PLAN-GATE]`「派活前必过」的窄例外，必须写死边界（r4 ①-1 致命）**
>
> 冲突所在：③ 派原型发生在 ⑧ Gate **之前**。若不写例外，未来执行者只有两条路——
> 在 ③ 前补一次 Gate（实证流退化回文本审），或**把任意实现声称成 spike 自行豁免 Gate**。
> 后者正是本规则体系一路在防的自我豁免通道。
>
> **例外条件（四条全中才成立，缺一即按标准流水线走 Gate）**：
> 1. 已通过 §4 的入口判据四条
> 2. 入口判定结论与决策表**已写入 journal**（写在派活之前，事后补记不算）
> 3. 该次产出是**一次性探测代码**，**不得直接交付**（晋级须走 §2⑨ 六步协议）
> 4. 简报里显式标注「本次为实证流 ③ 的 spike，受 §2③ 窄例外」
>
> **不在例外之内**：⑦ 形成的生产化 spec/plan **必须经 ⑧ 通过后**才能派 ⑨ 的实现。
> 即：**探测可以先派，交付不能先派。**

- 每候选一个独立工作区；**原型豁免 TDD**（spike 是一次性探测代码）
- 行数受 `[DELEGATION-BAND]` 约束，各候选独立计量
- 简报写明产物写回主仓 `runs/` 的绝对路径

### ④ 原型快审（fail 不阻断）

⚠️ **不得直接写「见 `ops/l2.md`」**：现行 L2 定义为**落地后完整变更集**的局部审查，
**不覆盖原型阶段**（已核实：`grep '原型\|spike\|实证流' ops/l2.md` 命中 0）。

**采用方案 B，不给实施者现场改选权**（r4 ④-1）：在 `ops/empirical-flow.md` 内定义
「原型快审」这一局部角色。**方案 A（改 `ops/l2.md` 扩大 L2 语义）已否决**，
理由：改动面更大，且会让 L2 同时承担两种生命周期不同的职责。

**原型快审的完整定义（五条须写死，否则不自包含 —— r4 ③-3）**：

1. **跨家族**：相对**该原型作者的家族**（原型由 codex 写 → Claude 审；反之亦然）
2. **审查对象**：**单个原型及其测量接口**，不是完整变更集
3. **只查**可能污染 ⑤ 数据的局部错误（接口用错、指标算错、数据泄漏、跑不起来）
4. **fail 不阻断**：挂了记「原型快审未生效」，照常进 ⑤
5. **不是 L2、不替代 ⑨ 的正式 L2**；**生命周期止于原型阶段**

### ⑤ 真跑（支点）

- 每候选 `runs/<日期>-<slug>-<候选名>/`：`config.json`、`metrics.csv`、`run.log`、`artifacts/`
- `config.json` 必含：`status`、`started_at`、**候选代码 diff hash**、**测量代码 hash**、
  **数据版本**、**种子**、**环境版本**
  （独立 worktree 的 `git_sha` 可能全是同一基线 SHA，标识不了未提交的候选实现）
- **跑挂了也是数据**：记 `status: failed` 并保留日志
- **公平性三条**：差距小于噪声不得判高下；各候选 debug 重试预算均等；性能类指标不并行跑
- **全部失败 / 差距小于噪声 → 按决策表：停止，或回 ①/③**（不得硬写 spec）

### ⑥A Codex sol ultra：基于证据生成并比较方案

采用 Plan-Gate 第二轮 Q2 给出的输出契约（逐字写进 ops 文件）：证据账本 → 方案集 →
条件化判断三段式；1–3 个方案由证据决定数量；允许「在条件 X 成立时优先 A」但**禁用
「最终方案」「应直接采用」等无条件定案措辞**；只剩一个方案时明写「当前只有一个可晋级方案」
并列出最强替代被否决的具体原因；**含未测关键机制的方案只能列为未验证假设，必须回 ③–⑤**。

### ⑥B 独立实验证据审阅（advisory）

> **定名理由（r3 ③-4）**：v2 叫「独立实证复核」，但工具集只给只读三件套、做不了重算，
> **名实不符会让「第二份叙述」被误当成「第二份实证」**。改为「审阅」，并显式声明不复现、不重算。

- 全新 Claude 上下文，**只读**（`Read`/`Grep`/`Glob`，不给 `Write`/`Edit`/`Bash`）
- 收：用户原话、候选/run 清单、测量代码与黄金样例、原始数据、哈希、候选代码、实验配置
- **不收**：⑥A 的 Sol 报告、L0 的观察/偏好/草拟结论
- 干：静态审阅测量有效性、候选间可比性、数据是否支持结论；从数据独立重建可行方案与反证
- **能力边界（须写进简报与报告）**：**不复现、不重算、不运行黄金样例**；
  报告须列出**实际读取了哪些文件**与**哪些项未核验**
- **不定案、不充当 Plan-Gate、不得称为 L2**
- 独立性的准确描述（四句都要写进文档）：
  - 相对 ⑥A 的 Sol —— 不同家族且互盲
  - 相对 L0 当前判断 —— 全新上下文
  - **相对 L0 的模型家族 —— 不独立**
  - **相对 ① 预先定义的候选/指标/测量材料 —— 不独立**，故消除不了共同输入框架造成的盲点

### ⑦ L0 定案（决策不外包）

- **L0 必须亲自对原始数据**（`[EVIDENCE-FIRST]`：⑥A/⑥B 报告是二手，`metrics.csv` 才是一手）
- 对照两份互盲报告，**形成分歧清单**（供 ⑧ 逐条回应）
- 可选其一、可合成、可都不选；**含未测关键机制的合成方案必须回 ③–⑤**
- spec 写清**为什么选它** + **什么样的数据会让我改选**
- **仅复述 ⑥A 的条件化首选不满足 `[OWNERSHIP]`**

### ⑧ Plan-Gate（硬门槛）

- 形态同 `ops/plan-gate.md`：1 个 `gpt-5.6-sol` + `ultra` + `-s read-only`，四维单审，
  spec+plan 同审；三闸 + 四维标题校验由 **L0 亲自**做
- **本流程专有的三条附加要求**：
  - 喂**全部候选（含落选）的原始数据**，并明令「以数据为准，凡 spec 说『实测表明 X』请回 metrics 自己核」
  - 喂 ⑦ 的**分歧清单**（⑥A 与 ⑥B 互盲报告的冲突处），要求**逐条回应**
  - 提供候选/run 清单、文件哈希与覆盖表，**要求输出逐候选核验状态**
    （走 stdin 只解决 `ARG_MAX`，不解决「是否真读完」）
- 简报**不提**方案源自另一次 sol 调用

### ⑨ 生产化：六步协议（**有顺序，不是并列条件**）

> **v2 的错误（r3 ③-1，致命）**：v2 把这些写成「同时满足的四个前置条件」，导致三处打架——
> 流程图写 L2→L3→回归、正文写「回归不达标不得进 L2/L3」、条件 4 又要求 L2/L3 对应最终 hash，
> 形成循环依赖。**后果是可实际触发的**：审查 hash A、复验或修复后交付 hash B，终检静默失效。
> v3 改为有顺序的协议，hash 一致性从「前置条件」降为**全过程不变量**。

1. **冻结**行为/验收契约、容差、测量流程 —— 契约源自需求与指标契约，**不得从赢家实现反推**；
   容差**在跑回归之前**定死，不得看见结果再调
2. **建立并验证验收测试** —— 至少让一个已知错误版本 / 落选候选 / 故障注入**真实失败**
   （防无断言、错 fixture、名不符实 —— 本机有前科）
3. **按 TDD 整理、加固**最终代码
4. **在候选最终 hash 上**跑验收测试 + 实证回归
5. **对同一 hash** 跑 L2、L3 终检
6. **任一实质修改使第 4、5 步的证据失效** —— **必须重跑第 4–5 步**（非重做第 1–5 步）

**回归失败的分流（v2「一律回 ⑦/⑨」过宽）**：
- 只是**实现缺陷** → 留在 ⑨ 修复并重跑第 4–5 步
- **实验推翻了机制选择或 spec** → 才回 ⑦，并重新过 ⑧

**TDD 的准确说法**：原型阶段豁免 TDD；决定晋级后先建立契约驱动且经有效性验证的测试，
此后的整理、加固与修改按 TDD 执行。**不得声称原型本身「补做后就变成了 TDD」。**

之后照常 `[PR-GATE]`。

## 3. 模型独立性与已知盲点（逐字采用 Plan-Gate 第二轮 Q6）

见 plan T1，该段整体写入 `ops/empirical-flow.md`。要点：

- 本流程提供**有限的流程独立性，不是完整的模型家族独立性**
- L0 与 ⑥B 同属 Claude，⑥A 与 ⑧ 同属 Codex，**本机没有第三个家族**——
  不得把任何一步称为完全独立的第三方裁决，不得声称同家族盲点已消除
- **治不了**：共享测量代码与黄金样例一起出错、目标或指标选错、遗漏关键候选、
  实验环境未覆盖真实条件、用户意图被误解、同家族在需求/设计/YAGNI 上共享先验
- **「唱反调」只是输出约束，不会自动创造新的先验或独立证据；提供全部数据不等于数据已被完整读取或证明正确**
- 冲突处置：两份报告冲突 / 测量有效性受质疑 / 关键结论仍只靠共同先验时，
  **不得按多数票或模型身份放行**——回测量、补跑，或由 L0 请用户裁定
- Plan-Gate 通过**只表示在已审材料中没发现未解决的阻断项**，不是全局正确性证明

## 4. 入口判据（逐字采用 Plan-Gate 第二轮 Q4）

四条**同时满足**才进实证流：① 至少两个关键机制有实质差异且可同条件运行的候选；
② 本次选择会直接改变后续方向，且至少一个主指标/硬约束必须真实运行才能获知；
③ **看到结果前**已写出决策表，至少两个会导致不同动作的结果区间；
④ 能留下可追溯的数据/配置/代码/测量代码哈希并能估计噪声。

**核心反证**：如果不存在任何合理实验结果会使 L0 改选、停止或补测，该任务不属于实证流。
「能写两个原型」或「跑一下更放心」不构成入口。

**入口判定与决策表须在原型实现和查看结果之前写入 journal。**
