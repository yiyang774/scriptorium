# 强制执行层（guard 系列 hook）· 唯一事实源

> **要改 guard、加新拦截规则、或被误拦时先读本文件。**
>
> 为什么需要这层：CLAUDE.md 是**放进上下文的文本**，与用户消息、工具输出、模型自己刚生成的
> 推理竞争注意力。会话一长，中段条款约等于不存在。实测规律：
> **能变成"产物 / 退出码"的条款生效，纯劝诫的不生效。**
> 本层把最该守的几条从"文本劝诫"升级为"机器闸门"。

## 1. 分级（只有真正不可逆的才硬拦）

| 级别 | 机制 | 拦什么 | 误拦代价 |
|---|---|---|---|
| 🔴 deny | `PreToolUse` exit 2 | PR 直接合并 / 推默认分支；审查调用缺 `-s read-only` | 高，故只收极窄两类 |
| 🟡 block | `Stop` exit 2 | 报了量词断言却没跑过任何检索命令 | 中，有三层逃生阀 |
| 🟡 block | `Stop` exit 2 | 说了第一人称未来承诺却本轮无任何工具调用 | 中，同三层逃生阀 |
| 🔵 记录 | `PostToolUse` | 命令与产出事实（`journal-facts.sh`，既有） | 无 |
| 🟢 文本 | CLAUDE.md / ops | 其余全部条款 | 无，但也没强制力 |

**分级原则**：能上 🔴 的只有"做了就回不去"的动作；判断题、风格题一律留在 🟢。
宁可漏拦不可误拦——guard 是护栏，不是安检门。

## 2. 文件

```
~/.claude/hooks/
├── guard-lib.sh        公共库（读 stdin、取字段、证据台账）
├── guard-pretool.sh    🔴 PreToolUse 硬拦
└── guard-stop.sh       🟡 Stop 承诺闸 + 证据闸
~/.claude/.guard/<session_id>/evidence.log   本轮证据台账（7 天自动清理）
```

既有的 `journal-*.sh`、`preflight-l2-reminder.sh` **不属本系统**，未改动其逻辑
（仅修了 preflight 的路径 bug，见 §6）。

## 3. 🔴 PreToolUse 硬拦（两条）

### 1. PR 直接合并 / 推默认分支 —— 违反 `[PR-GATE]`

拦 `gh pr merge`、`git push ... main|master`。**不拦** `gh pr create`、`gh pr view`、推普通分支。
拦截时 stderr 给出完整替代路径（开 PR → 读 pr-merge.md → codex 审 head SHA → 用户拍板）。

### 2. 审查调用缺 `-s read-only` —— 违反 `[GRANT-PERMISSIONS]`

仅当命令是 `codex exec` **且**含 review 子命令或审查关键词（对抗式审 / Plan-Gate / 快审）时才检查。
理由：审查者动手改自己要审的东西即失去审查意义；裸 `review` 无法判定是否只读，视为**无效发起**。

> **诚实边界**：字符串匹配总有绕法（`eval`、变量拼接、heredoc、base64 后执行）。
> 本层防的是"顺手就做了"，**不声称能防有意规避**。

### 判定必须【引号感知分段】——两次实测误拦换来的

上线当天连撞两次误拦，都是判定粒度问题：

| # | 错误做法 | 症状 |
|---|---|---|
| ① | 整串子串匹配 `case "$CMD" in *"gh pr merge"*)` | 测试脚本里**出现**该字面量即被拦——它是被测数据不是被执行的命令 |
| ② | `sed` 按 `;&&\|\|` 分段（无引号语义） | `P='{"cmd":"cd /tmp && gh pr merge 9"}'` 里的 `&&` 被切开，后半段恰以该动作开头 → 仍误拦 |

**现行做法**：`guard-split.py` 做引号感知分段（只在**引号外**的 `; \| & 换行` 处切），
再要求该段**以目标动作开头**。分段器有独立单测，改判定逻辑必须同时跑。

> **为什么独立成 .py 文件**：内联 python 需要三层引号嵌套（bash 单引号 → python 单引号 →
> 匹配用的引号字面量），实测写坏过一次（生成的脚本里 python 字符串被 shell 吃掉）。
> 凡需嵌套三层引号的逻辑，一律独立成文件。

### 急停开关的一个实测陷阱

`export GUARD_OFF=1 && <被拦命令>` **无效**——钩子在命令执行**之前**就跑了，
那时环境变量还没生效。被拦住时要脱困，用**文件式**急停：

```bash
touch ~/.claude/.guard-off     # 立即生效（钩子每次都读文件）
rm -f ~/.claude/.guard-off     # 记得解除
```

`GUARD_OFF=1` 只在**由外部环境预先导出**时有效（如整个 shell 会话开头就 export）。
**注意**：忘记解除 `.guard-off` 会让整套 guard 静默失效——自测里 13 项"应拦"用例
全部返回 0 就是这个原因。`guard-selftest.sh` 跑出大批 FAIL 时，先查这个文件在不在。

## 4. 🟡 Stop 证据闸（治"浅尝辄止"）

### 判定

本轮回复含**量词断言** AND 本轮**无证据命令** → `exit 2` 打回。

四类量词断言（正则，剔除代码块与引用块后匹配）：

| 类型 | 例 |
|---|---|
| 计数 | "共 21 处"、"3 条 must-fix"、"11 项全绿" |
| 全称 | "全部通过"、"所有引用均已修复"、"一律正确" |
| 否定 | "没有任何残留"、"零残留"、"未发现任何问题" |
| 验收 | "11/11 通过"、"7/7 一致" |

**证据** = 本轮跑过检索/计数类 Bash 命令（grep / wc / find / diff / numstat / shasum /
pytest / jq / awk / node --check / bash -n 等），由 `guard-pretool.sh` 顺带记账。

### 为什么是这四类

实测来由（同一会话内连续三次）：
1. 口头报"编号漂移 5 处"，机械 grep 后实为 **21 处**——从规律生成清单，没逐个数
2. spec 写"21 + 2 = 23"，python 求和实为 **21**——裸条目号重复计了一次
3. 子代理报"grep 无输出、未发现残留"，实为 grep 被 zsh glob 挡下**根本没执行**——假绿

三次的共同点：**推断出来的结论与查出来的结论，在生成时的主观确信度完全相同**，
中间没有任何"我还没读"的信号。所以只能靠外部闸门。

### 三层防误拦（任一生效即放行）

1. `stop_hook_active=true` —— 已打回过一次就不再拦（防死循环，抄 `journal-stop.sh` 的做法）
2. 回复里写 `[无需证据: 理由]` —— 显式逃生阀
3. `export GUARD_OFF=1` 或 `touch ~/.claude/.guard-off` —— 全局急停

### 被拦了怎么办

三选一：**A** 跑一条命令核实并贴出输出；**B** 把结论改成不带量词的表述；
**C** 确属无需核实（纯对话、引用他人结论）→ 写 `[无需证据: 理由]`。

## 5. 🟡 Stop 承诺闸（治"说了要做、然后结束回合"，2026-08-05 新增）

### 判定

本轮回复含**第一人称未来承诺** AND 本轮**无任何工具调用** → `exit 2` 打回。

| 类型 | 例 |
|---|---|
| 我+动词 | "我会记进 journal"、"我将把这个改到 spec 里"、"我来补一份终检" |
| 时间副词 | "稍后补一份报告"、"接下来记录"、"待会儿改" |

**与证据闸的分工**：证据闸问"**有没有查**"（检索类命令 → `evidence.log`）；
承诺闸问"**有没有做**"（任何工具，含 Edit/Write/Task → `action.log`）。两本台账分开记，
因为"改完文件才作的承诺"不该被拦，而"只查不做的空承诺"该拦。

⚠️ **记账点必须在 `guard-pretool.sh` 的 `[ "$TOOL" = "Bash" ] || exit 0` 之前**——
否则 Edit/Write 全不记账，一改完文件就误拦。

### 来由（实测）

声明"这条豁免我会记进 journal 留痕"后**直接收尾，留痕没做**，靠下一轮自查才补上。
与证据闸同源：**打算做和已经做，在生成时的主观确信度完全相同**，中间没有"我还没做"的信号。

### 被拦了怎么办

三选一：**A**（默认）本轮就做掉——能现在做就别写成承诺；
**B** 改写成不含承诺的表述，如"待办：xxx，本轮未做"；
**C** 确属下一轮才能做（依赖用户输入 / 外部结果）→ 写 `[无需证据: 理由]`。

### 已知边界

只看**最后一条 assistant 消息**（与证据闸同）；跨轮承诺（这轮说、下轮做）不拦，
本就不该拦。台账在每个 Stop 退出路径清空，含 `stop_hook_active` 早退路径。

## 6. 顺带修复的既有 bug

`settings.json` 里 `preflight-l2-reminder.sh` 原写作 `$CLAUDE_PROJECT_DIR/.claude/hooks/...`，
但该脚本实际在 `~/.claude/hooks/`。**实测**：在 `motivation-figure`、`paperI_motivation`
等项目下该路径不存在 → hook 一直**静默失效**。已改为绝对路径。

> **教训（对所有用户级 hook 通用）**：`$CLAUDE_PROJECT_DIR` 按当次工作目录解析。
> 用户级 hook（配在 `~/.claude/settings.json`）**必须写绝对路径**，否则只在
> 恰好有同名文件的项目里生效。

## 7. 观察期与触发记账

每次拦截追加一行 TSV 到 `~/.claude/.guard/triggers.tsv`（时间/钩子/类型/会话/摘要，摘要截 120 字）。
**只追加不改写**——同任务日志的原则。

```bash
~/.claude/hooks/guard-report.sh        # 看：拦了几次、按类型/按日分布、最近 10 条
echo '2026-08-05 09:4' >> ~/.claude/.guard/false-positives.txt   # 标注一次误拦（写时间戳前缀）
```

**判读阈值**：日均 >5 次 → 可能过于骚扰，收窄正则；误拦率 >20% → 判定逻辑要修，别硬扛；
全程 0 次 → 要么没触发（好），要么钩子没生效（查 settings.json 与 `.guard-off`）。

> 记账的动因：不记就只能凭印象回答"误拦多不多"——那正是本层要治的毛病。

## 8. 写文档时的已知误拦：命令反例会被当成真命令（2026-08-05 实测）

**症状**：用 heredoc 写文档 / 留痕时，正文里**引用一条反例命令**，被 🔴 拦截 2 拦下。

**根因**：分段器在 `;` `&&` `|` 处切段，若反例里恰好有分隔符，后半段可能以 `codex exec` 开头
→ 被判为"审查调用缺 `-s read-only`"。实测触发原文（脱敏改写后）：
在同一行里先 `echo` 一个只读标志、再用 `;` 接一条不带该标志的 codex 审查命令。

**判据不是"含 `codex exec`"，而是"它是否落在某个段的开头"**。实测对照：

| 文档写法 | 是否触发 |
|---|---|
| 反例里有 `;` 把 `codex exec` 切到段首 | ⚠️ 拦 |
| `` 派法：`codex exec ... -o <留痕路径>` ``（不在段首） | ✅ 不触发 |
| `# 避免测试脚本里嵌了 "codex exec ... review" 字面量`（不在段首） | ✅ 不触发 |

**处置（2026-08-05 用户裁定选 B，护栏零削弱）**：**改文档写法，不改 guard**。
把反例改成散文描述 + 指向自测用例，不要在文档里逐字复刻带分隔符的完整命令。

> **为什么不给 guard 加"含 `...` 即视为示例"的排除**：那会开一个真口子——
> 判定"这是示例不是命令"本质上要读意图，而 guard 只能看字符串。
> 误拦的代价是换个写法，漏拦的代价是审查者带写权限跑起来。**宁可误拦。**
> （本条修改曾被权限分类器拦下，判为"agent 自行削弱自己的安全钩子"——拦得对。）

## 9. 加新拦截规则的流程

1. 先问：这条能不能变成**脚本/产物**（第 2 档），而不是拦截？能就别拦。
2. 确需拦截 → 判断级别：**做了就回不去** → 🔴；**能事后补救** → 🟡。
3. 在对应脚本里加分支，**必须同时加实测用例**（造出该拦的和不该拦的各若干）。
4. 跑全量测试：`~/.claude/hooks/guard-selftest.sh`
5. 更新本文件的分级表。

## 10. 诚实边界

- 字符串匹配可绕，不防有意规避（见 §3）。
- Stop 闸只看**最后一条 assistant 消息**，前面轮次的无证据断言抓不到。
- 证据判定是**粗粒度**的：跑过任意检索命令即算有证据，不校验"这条命令是否真能支撑那个数字"。
  精确配对需要语义理解，不是 hook 能做的——那仍归 L2/L3 审查兜。
- 本层**不替代**任何硬门槛（Plan-Gate / L3 / PR-GATE）；它只是让"忘了做"变难。
