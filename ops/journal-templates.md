# 任务日志 / 错误档 模板与字段（全局唯一事实源）

> 从项目内 `docs/superpowers/journal/README.md` 提升为全局——新项目不必先有那个文件。
> 建档时把需要的部分复制过去即可。

本目录承载**任务日志**与**项目错误档**。硬规则写在全局 `~/.claude/CLAUDE.md` §6，
本文件只放**模板与字段说明**——按需读取，不占常驻上下文。

- `YYYY-MM-DD-<slug>.md` —— 任务日志，一任务一份
- `MISTAKES.md` —— 项目错误档
- `verify-band-rules.sh` —— 行数复核与错误档筛选的验收脚本（可直接跑）

## 1. 任务日志模板

```markdown
# 任务日志：<任务名>
状态：进行中 | 已交付 | 已搁置
最后更新：YYYY-MM-DD

## 📍 当前状态（每次更新覆写此节 —— 断片后先读这里）
- 进行到：<阶段 X / 第 N 步>
- 下一步：<具体到可直接开工的一句话>
- 未决问题：<等用户裁定的 / 悬而未决的>
- 关键路径文件：<path:line>
- 已定裁决（仍生效的约束，一行一条）：
  - <结论> —— <一句理由>

## 📜 事件流（只追加，绝不改写历史）
- [MM-DD HH:MM] <事件> —— <证据指针>     # 同日多事件时 HH:MM 便于定位；
                                          # 单日少量事件可简写 [MM-DD]
```

### 快照五字段说明

| 字段 | 写什么 | 为何需要 |
|---|---|---|
| `进行到` | 当前阶段 / 第几步 | 断片后的定位锚 |
| `下一步` | 具体到可直接开工的一句话 | 恢复后不必重新决策 |
| `未决问题` | 等用户裁定的、悬而未决的 | 防止未决事项被遗忘 |
| `关键路径文件` | `path:line` | 省去重新查找 |
| `已定裁决` | 仍生效的约束，结论 + 一句理由 | **仅记阶段与下一步无法恢复"为什么这么定"** |

### 必记事件（其余不记；派活/交付结果、L2/L3 各拆两条，故表内 9 行）

| 事件 | 记什么 |
|---|---|
| 用户裁定 | 结论 + 关键理由 |
| Plan-Gate 收口 | 过 / 打回、致命项处置 |
| **实证流入口判定** | **入口判据四条的逐条结论 + 决策表**（`ops/empirical-flow.md` §1）。**必须写在任何 Gate 前实现派活之前**（含 ① 测量代码与 ③ 候选原型）——这是两类窄例外能否成立的前提之一，**事后补记不算数** |
| 派活 | 派给谁、任务、预估行数 |
| 交付结果 | 实际行数、测试结果；**若 >400 行须附超出原因**（`[DELEGATION-BAND]` 要求）—— **与派活分两条追加，不回写历史** |
| L2 审查 | `must-fix` / `nit` 各几条、采纳或判误报及理由 |
| L3 审查 | 第几轮、按该次审查自身的严重度分级计数、采纳或判误报及理由 |
| 阻塞与未决 | 卡在哪、等谁 |
| 交付/合并 | PR 号、SHA、测试实据 |

涉及子代理产出或审查意见的事件**须带证据指针**（`.plangate/<run>/…`、PR 号、测试命令），
不能只写结论。

## 2. 错误档条目模板

```markdown
## [E00N] YYYY-MM-DD · <一句话标题>
- **有效性**：active
- **处置**：未修复
- **触发场景**：<什么时候会碰上——扫描入口，只读这行即可判定相关性>
- **错误做法**：<具体做了什么>
- **后果**：<造成了什么，给人判断轻重>
- **正确做法**：<该怎么做，可直接抄进简报>
- **根因**：<为什么会错，防只治标>
```

### 字段说明（条目共 9 个数据字段 + 标题）

| 字段 | 取值 / 写什么 | 用途 |
|---|---|---|
| `[E00N]` 编号 | 顺序编号 | 便于口头指代与交叉引用（**注意：简报里不能只写编号，须逐字抄字段内容**——子代理读不到本文件） |
| 标题 | 一句话概括 | `## [E00N] 日期 · <标题>` 中的标题部分 |
| 日期 | `YYYY-MM-DD` | 记录时间 |
| **`有效性`** | `active` / `superseded-by-E0NN` / `obsolete` | **决定是否进简报**——只有 `active` 进 |
| **`处置`** | `未修复` / `已规避` / `已修复` | 仅供人判断轻重，**不影响是否进简报** |
| `触发场景` | 什么时候会碰上 | **扫描入口**，派活前只读这列 |
| `错误做法` | 具体做了什么 | 供人对照理解；**不进简报**（简报只抄 `触发场景`+`正确做法`） |
| `后果` | 造成了什么 | 提供"值得警惕"的分量 |
| `正确做法` | 该怎么做 | **进简报的两字段之一**（另一个是 `触发场景`）|
| `根因` | 为什么会错 | 防只治标；判断新错误是否与旧条目同源 |

> **两个状态字段为何正交**：`有效性` 管"这条还算不算数"，`处置` 管"这个坑修没修"。
> **未修复的坑仍是 `active`，照样进简报，而且最该进**——曾误设为单一字段，
> 导致按写入规则填"未修复"的条目永远不满足读取规则"只取 active"，
> 最该预警的错误反而进不了简报。
