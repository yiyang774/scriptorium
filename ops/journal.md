# 任务日志与错误档（从 CLAUDE.md §6 外置）

> **要建档、写日志或扫错误档前，先读本文件**


> **模板与字段的唯一事实源：`~/.claude/ops/journal-templates.md`（全局，必定存在）。** 项目内 `docs/superpowers/journal/README.md` 若有则为补充，**不得依赖它存在**。

### 任务日志
- **何时建（正面列举，命中任一即建，未命中即不建）**：① 走 brainstorm + plan 的复杂任务；② 进入 Plan-Gate；③ **任一次实现交付（L1 委派 __或__ L0 主循环直接实现）实际 >400 行实现代码，或触发`[DELEGATION-BAND]`的「判不准就从严」兜底原则**（两者都要求写明理由，故此时必须有日志可写——否则出现"该记却无处可记"的死锁）；④ **已产出 spec/plan 且决定据其落地实施**（不含跨会话条件——决定实施的那一刻即触发，不必等跨会话）；⑤ **判定进入实证流**（`ops/empirical-flow.md`）——**必须在任何 Gate 前实现派活之前**（含 ① 共享测量代码与 ③ 候选原型）记入口判据四条的逐条结论 + 决策表，事后补记不算数（这是两类窄例外能否成立的前提之一）。**未命中上述五条的一律不建**——纯对话、小事实查询、≤400 行的普通委派均不建档，**即使跨会话也不建**。
  > ④ 的判据是**"产出是否会成为落地实施的依据"**，而非是否跨会话：§6允许纯口头咨询产出**不落地**的 spec/plan（并标记"未过 Plan-Gate、不得作为派活依据"），那种不建档；一旦决定据其实施，**同会话内当场即触发 ④**（此时也须按 §6补跑 Plan-Gate）。否则日志本身成为过度编排。中途才命中信号的，**当场补建档**并补记已发生的关键事件。
- **放哪**：项目内 `docs/superpowers/journal/`，命名 `YYYY-MM-DD-<kebab-slug>.md`，**日期取创建日不随更新变**；slug 锚定「任务」而非「动作」（`b2-type-offset-calibrator` 而非 `fix-bug`），**同一任务永远追加同一份**；与 specs/plans 同 slug 对齐。**跨多项目的单一任务**：以**该任务 spec 所在项目**为日志宿主（无 spec 则取改动量最大者），其余项目不另建——一任务一份日志优先于按项目切分。
- **形态**：**头部状态快照（每次覆写）+ 尾部事件流（只追加）**。快照五字段：`进行到` / `下一步` / `未决问题` / `关键路径文件` / `已定裁决`（仍生效的约束，一行一条含结论+理由——仅记阶段与下一步不足以恢复"为什么这么定"）。
- **只追加、绝不改写历史**：否则模型会"整理"掉不利记录，日志失去证据价值（呼应`[EVIDENCE-FIRST]`）。不设长度上限、不做归档。
- **七类必记事件**（其余不记）：**用户裁定** / **Plan-Gate 收口** / **实证流入口判定**（入口判据四条逐条结论 + 决策表，**须在任何 Gate 前实现派活之前写**，含 ① 测量代码与 ③ 候选原型）/ **派活**（派给谁、任务、预估行数）与**交付结果**（实际行数、测试结果；**若 >400 行须附超出原因**）——**分两条追加，不回写历史**/ **L2 审查**（`must-fix` / `nit` 各几条、采纳或判误报及理由）与 **L3 审查**（第几轮、按该次审查自身的严重度分级计数、采纳或判误报及理由）——**各按其输出契约记，不强套统一分级**/ **阻塞与未决** / **交付/合并**（PR 号、SHA、测试实据）。涉及子代理产出或审查意见的事件**须带证据指针**（`.plangate/<run>/…`、PR 号、测试命令），不能只写结论。
### 会话事实自动抽取

`journal-stop.sh` 在会话结束时自动跑 `hooks/scribe-extract.py`,从 transcript **机械抽取**本次会话的事实,追加到 `.facts-<日期>.md`:用户消息、**AskUserQuestion 的问答对(裁定)**、派活的 model+任务、codex 调用档位、git commit / PR。**不调任何模型,机械抽取**。

L0 在 Stop 被拦时会看到这份草稿,**据此补写"为什么这么定"再进事件流**——草稿只有"发生了什么",没有"为什么",后者不能外包。

> **为什么用机械抽取不用便宜模型**:transcript 里满是 guard 提示、AskUserQuestion 之类"指令样"文本,便宜模型反复误以为那是给自己的任务,改提示词或源头过滤都没根治。**把充满指令的文本喂给模型让它"别当指令",本身就是不稳的设计。** 机械抽取零污染、100% 可复现。
>
> 更一般的教训:**"忘了去记"靠 hook 解决(不依赖记忆);"记得不准"靠机械抽取解决(不依赖理解)。派便宜模型救不了前者**——派它的那一步同样会被忘。

- **诚实边界**：本层**无任何机器强制**，全靠 L0 主循环自觉；会话边界（压缩 / 结束 / 启动）的自动兜底**已由 `~/.claude/hooks/` 落地**（2026-07-26 实测通过）；**事件流内容仍靠自觉**。

### 项目错误档 `<项目>/docs/superpowers/journal/MISTAKES.md`
- **收什么**：**本项目特有**的坑。跨项目通用教训仍归 `memory/*.md`；过程流水归任务日志——三者不重复。
- **两个正交状态字段**：`有效性`（`active` / `superseded-by-E0NN` / `obsolete`）决定**是否进简报**；`处置`（`未修复` / `已规避` / `已修复`）仅供人判断轻重。**未修复的坑仍是 active，照样进简报，而且最该进**。
- **只追加**：条目正文写下不删不改；认识变化写新条目并把旧条目 `有效性` 改为 `superseded-by-E0NN`（**仅允许改这两个状态字段**）。**一条一错**，不合并"顺便还发现…"，否则触发场景失去检索力。
- **何时写**：错误**确认后立即写**（不必等修复完成），此时 `有效性: active` + `处置: 未修复`；修复后只改 `处置`。等修复才写会留下预警空窗。
▶ **别手工扫——跑 `~/.claude/bin/mistakes [关键词]`**：
  自动向上找 MISTAKES.md、只出 `active` 条目、只含 `触发场景`+`正确做法` 两字段、
  格式直接可粘进简报。`mistakes --list` 看全部条目，`mistakes 测试` / `mistakes GPU` 按任务筛。
  手工扫会漏条目、会抄错格式、会顺手把"后果/根因"也抄进去稀释重点。

- **派活前必扫（关键）**：写简报前扫 `触发场景` 列，**只取 `有效性: active` 的相关条目**，把其 **`触发场景` + `正确做法` 两字段**逐字抄进简报（不抄后果/根因——那是给人判断用的，塞进简报只会重现`[DELEGATION-BAND]`要治的"单次信息量过大"）。**不是给路径让子代理自己看**——它无会话记忆，也未必会去读。
- **诚实边界**：本条**无机器强制**，Claude Code 无法在 Agent 调用前拦截注入。若日后发现重犯，应把必扫动作前移到规划阶段（`CLAUDE.md §2.1`），而非继续加规则文字。
