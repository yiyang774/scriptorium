# 实证流：并行造原型 → 跑出数据 → 后置对抗审（唯一事实源）

> **动因**：Plan-Gate 若放在最前面，审的是一份还没实现的 spec 文本，
> 模型只能靠推理猜漏洞，于是挑出大量"理论上可能"的问题，且每轮修复会诱发下一轮新矛盾。
>
> **实测（2026-08-03 CLAUDE.md 重构）**：四轮 Plan-Gate 共 64 条意见，
> r1 是真问题，r2 是"我修 r1 时加条款造成的越界"，r3 是"修 r2 做减法时删改不同步"，
> r4 有 4 条是修 r3 时新引入的——**后三轮过半是审查自己诱发的**。
> 而同一份文件的 L3 终审**一轮就给出 5 个真漏洞**，因为它审的是**成品**不是计划。
>
> **本流程把对抗审移到后面**：前面并行造原型并**真跑出数据**，
> 让 frontier 模型拿到**事实**而非主张——事实不需要说服，只需要解释。
>
> ⚠️ **但 Plan-Gate 没有被取消，只是移到了第 ⑧ 步**（2026-08-07 用户裁定）：
> "新方案的产出还是需要过 Plan-Gate，不能仅仅听 codex sol ultra"。
> **两条路都过 Plan-Gate 与 L3，区别只是 Plan-Gate 的时点。**

## 1. 入口判据：什么任务走实证流

**四条同时满足才进入，缺一即走标准流水线：**

1. 存在至少两个事前可信、**关键机制有实质差异**的候选；各候选能在同一接口、数据、
   资源预算和测量流程下运行。仅把同一方案改名、改参数，或配一个明显更差的陪跑项，不算两个候选。
2. 本次选择会直接改变后续 spec、实现方向或资源投入；至少一个预先声明的主指标或硬约束
   **必须通过真实运行才能获知**，现有静态证据不足以完成选择。
3. **在看到结果之前**，L0 已写出可执行的决策表：主指标、硬约束、噪声口径、最小有意义差距，
   以及不同结果区间分别触发"选 A""选 B""无法区分并补跑""全部停止"。
   至少必须存在两个会导致不同后续动作的合理结果区间。
4. 各候选能留下可追溯的原始数据、配置、代码与测量代码哈希，并能估计噪声；
   否则实验只能作为探索材料，**不得直接支撑定案**。

> **核心反证**：如果不存在任何合理实验结果会使 L0 改选、停止或补测，那么该任务不属于实证流。
> 仅仅"能写两个原型"或"跑一下更放心"**不构成入口**。

**入口判定及决策表必须在【任何 Gate 前实现派活之前】（含 ① 共享测量代码与 ③ 候选原型）、
且在查看实验结果之前写入 journal**（见 `~/.claude/ops/journal.md`）。
任一条件不成立时，走标准流水线或单独的探索性 spike，
**不得把探索结果称为实证流定案证据**。
⚠️ **这种「单独的探索性 spike」两个例外都不享受**——
Gate 前派活例外只对**已通过本节四条判据的实证流 ③ 候选原型与 ① 共享测量代码**成立；
**TDD 例外只对 ③ 候选原型成立**（① 的测量代码是后续所有比较的地基，照常走 TDD）。

## 2. 九步流程

> **编号口径唯一**：九个主步骤；⑥A/⑥B 是第 ⑥ 步的两个并行分支，不单独计步。

```
① 预注册：候选 + 指标契约 + 决策表 + 共享测量代码（只写一份，过黄金样例）
② 设计审 ───────────────────── 判定测法不公平 → 回 ①
③ 并行派 N 个 L1 写原型（spike，独立工作区）
④ 原型快审（跨家族，fail 不阻断）
⑤ 真跑 → runs/<日期>-<slug>-<候选名>/
   └─ 全部失败 / 差距小于噪声 → 按 ① 的决策表四分流：
      预注册过的补跑→回 ⑤ / 需新候选或改口径→回 ① / 某候选实现坏了→回 ③ / 无可挽回→停止
⑥ 互盲分析（两分支并行）
   ⑥A Codex sol ultra：证据账本 → 方案集 → 条件化判断
   ⑥B Claude 全新上下文：独立实验证据审阅（advisory，只读）
   └─ 任一分支提出含未测关键机制的方案 → 先回 ① 补预注册，再走 ③–⑤
⑦ L0 定案（拆三小步）
   ⑦A L0 亲自核原始数据 → 对照两份互盲报告形成分歧清单
   ⑦B 强制 interview-me 意图对齐（无条件）→ 固化用户意图/偏好/非目标 + 处置意向（五种之一）
   ⑦C 按 ⑦B 处置意向分支执行（只有"选其一/合成"才写 spec/plan 进 ⑧）
⑧ Plan-Gate：Codex sol ultra 审 L0 的 spec/plan（硬门槛）
⑨ 生产化：六步协议 → PR-GATE
```

### ① 预注册：候选 + 指标契约 + 决策表 + 共享测量代码

- ≥2 个**关键机制有实质差异**的候选（改名 / 改参数 / 明显更差的陪跑项不算）
- **指标契约**：列名 + 口径 + **噪声口径**（多种子 / 置信区间）+ **主指标 + 硬约束 + 平局处置**，
  逐字写进每份 L1 简报
- **决策表**：看结果前写死"什么结果区间 → 触发什么动作"，至少两个会导致不同动作的区间
- **实证回归容差的公式在此冻结**：⑨ 的容差**不得到 ⑨ 才首次决定**——那时赢家表现已看完，
  可以倒推一个容易通过的数。做法：**① 冻结计算公式**（含聚合范围、舍入、缺失值处置），
  若数值须由 ⑤ 的噪声估计得出，则**数值写进 ⑦C 的 spec 并经 ⑧ 审查**，⑨ 只执行不设定
- **测量代码只写一份**，候选只实现被测接口；**须先用已知结果的黄金样例跑一遍**
  —— 共享代码保证各候选**用同一套测量逻辑与指标算法**（候选之间的机制差异是刻意的）；
  黄金样例**能发现部分系统性错误，提供一次非生成式检查**。
  ⚠️ **不得写成"黄金样例解决 / 证明了正确性"**：样例与测量代码可能一起错（见 §4）
- 冻结并记录：测量代码 hash、数据划分、种子、环境版本

### ② 设计审（advisory，fail 不阻断）

**一个便宜档、两个问题**（`gpt-5.6-luna max` + `-s read-only`；
若测量代码是本次新写的，升 `gpt-5.6-sol xhigh`）：

> 下面是我列的 N 个候选方案与验证指标。只回答两个问题：
> ① 有没有明显该试、但没被列进来的方案？
> ② 这套指标与测法，能不能公平地分出高下？
> 每条给：一句话描述 + 为什么可能更好 / 哪里不公平 + 怎么验。没有就只回"无遗漏"。

**为什么需要这步**：实验数据能证伪我提出的方案，**证伪不了我根本没提的方案**。
我设计实验、我跑、我整理——我没想到的就不会出现在材料里，这是本流程最大的盲区。

- 补上来的方案可判不适用，但**必须写理由**；**若判定确实该试 → 回 ① 重新预注册**
  （补进候选表与决策表后再往下走，不得半路塞一个没预注册的候选）
- **模型审查是 advisory；测量代码另有黄金样例这道非生成式检查**（两者都不是正确性证明）
- 调用挂了：记「设计审未生效」照常往下（硬门槛是 ⑧，不是这里）
- **判定测法不公平 → 回 ①**

### ③ 并行派 N 个 L1 写原型（spike）

> #### ⚠️ 本步是 `[PLAN-GATE]`「派活前必过」的窄例外
>
> **冲突所在**：③ 派原型发生在 ⑧ Gate **之前**。若不写例外，未来执行者只有两条路——
> 在 ③ 前补一次 Gate（实证流退化回文本审），或**把任意实现声称成 spike 自行豁免 Gate**。
> 后者正是本规则体系一路在防的自我豁免通道。
>
> **例外条件（四条全中才成立，缺一即按标准流水线走 Gate）**：
> 1. 已通过 §1 的入口判据四条
> 2. 入口判定结论与决策表**已写入 journal**（写在派活之前，事后补记不算）
> 3. 该次产出**在 Gate 前的用途仅限探测**，**不得直接交付**
>    （原型代码只有经 ⑧ 与 ⑨ 后才可能成为交付物）
> 4. 简报里显式标注**对应标签**（下面两类各用各的，不得混用）
>
> **Gate 前授权对象共两类**（L3 实测指出的死路：① 要求 ③ 之前就有测量代码并跑过黄金样例，
> 而例外只写了"候选原型"，于是非琐碎的测量代码派 L1 违反 `[PLAN-GATE]`、L0 亲写又违反委派纪律）：
>
> | | **③ 候选原型** | **① 共享测量代码** |
> |---|---|---|
> | 简报标签 | 「本次为实证流 ③ 的候选原型，受本节窄例外」 | 「本次为实证流 ① 的共享测量代码，受本节窄例外」 |
> | 范围 | 关键机制 + 测量接口的最小代码 | 只实现指标契约里列明的算法 + 黄金样例，**不含任何候选机制** |
> | **TDD** | **豁免**（一次性探测） | **不豁免，照常 TDD** —— 它是后续全部比较的地基，算错则所有数据一起错 |
> | 正确性门槛 | 交给 ④ 原型快审 | **必须跑通黄金样例才能进 ③** |
>
> 其余三条边界（入口判据已过 / 判定与决策表已写进 journal / 用途仅限探测不得直接交付）两类通用。
>
> **不在例外之内**：⑦C 形成的生产化 spec/plan **必须经 ⑧ 通过后**才能派 ⑨ 的实现。
> 一句话：**探测可以先派，交付不能先派。**

- 每候选一个**独立工作区**（worktree / 目录副本），避免互相污染
- 一条消息发多个 `Agent` 调用 / 多个 codex 后台任务
- 简报必带：指标契约（①）、`[SELF-CONTAINED-BRIEF]` 常规要件、`bin/mistakes` 查出的相关坑、
  产物写回主仓 `runs/` 的**绝对路径**
- **原型豁免 TDD**，但**范围锁死**：只允许实现「候选间待比较的**关键机制** + 跑通**测量接口**」
  所需的最小代码，**不得顺带写出接近生产态的完整实现**——否则 ⑨ 的"按 TDD 整理"会退化成
  无改动步骤，核心交付代码实际从未按 TDD 产生。**默认去向是弃用**；赢家可晋级但须走 ⑨ 全流程
- 行数仍受 `[DELEGATION-BAND]` 约束，各候选独立计量

### ④ 原型快审（fail 不阻断）

⚠️ **不是 L2**。L2 审的是**落地后的完整变更集**，本步审的是**原型阶段的单个候选**——
生命周期与对象都不同。故在本文件内定义这个局部角色，**不扩大 `ops/l2.md` 的语义**；
`ops/l2.md` 侧已相应写明该窄例外。

**完整定义（五条）**：

1. **跨家族**：相对**该原型作者的家族**（原型由 codex 写 → Claude 审；反之亦然）
2. **审查对象**：**单个原型及其测量接口**，不是完整变更集
3. **只查**可能污染 ⑤ 数据的局部错误（接口用错、指标算错、数据泄漏、跑不起来）
4. **调用失败不阻断**：挂了记「原型快审未生效」，照常进 ⑤
5. **不是 L2、不替代 ⑨ 的正式 L2**；**生命周期止于原型阶段**

> **「fail 不阻断」只针对调用失败，不针对已发现的缺陷**：
> ④ 报出会污染 ⑤ 的问题（指标算错、数据泄漏等）时，该候选须**先修复并重新快审，
> 或标为无效候选**——**其指标不得用于定案**。
> ⚠️ **但 ④ 的报告是二手（`[EVIDENCE-FIRST]`）**：淘汰一个候选之前，
> **L0 必须亲自回到代码/工件里核实那个缺陷真实存在**。
> 只凭一份二手报告淘汰候选，等于让 ④ 的误报直接改变最终选择。

### ⑤ 真跑，产出数据（本流程的支点）

**每个候选一个 `runs/<日期>-<slug>-<候选名>/`**，含：

- `config.json` —— 必含 `status` / `started_at` / **候选代码 diff hash** / **测量代码 hash** /
  **数据版本** / **种子** / **环境版本**
  （独立 worktree 的 `git_sha` 可能全是同一基线 SHA，标识不了未提交的候选实现）
- `metrics.csv` —— 按 ① 的契约，列名口径完全一致
- `run.log`
- `artifacts/` —— 重产物（已 gitignore）

跑完 `~/.claude/bin/exp-index` 生成 `EXPERIMENTS.csv` 横向对比表。

> **跑挂了也是数据**：OOM / 超时 / 不收敛 / 结果异常 —— 这是最有价值的信息之一。
> **记 `status: failed` 并保留日志，绝不悄悄丢掉。**

**公平性三条（都有本机前科）**：

- **差距小于噪声时不得判高下**（前科：种子间 sd 0.089，而信号只有 0.011）
- **各候选 debug 重试预算均等**，超了就记 failed——不许偏爱的候选一直救、别的留在失败态，
  那比较就是偏心确认
- **性能类指标不得并行跑**（前科：BLAS 超订，208 核开 20 worker 反而 49 分钟零产出）

▶ 跑之前先 `Read ~/.claude/ops/preflight.md`。布局细则见 `~/.claude/ops/project-layout.md`。

**按 ① 的决策表分流（不得硬写 spec）**：

- 决策表已预注册"补跑"方案（如加种子、扩样本）→ **回 ⑤ 直接补跑**，不必重走 ①③
- 需要新候选或改指标口径 → **回 ①** 重新预注册
- 只是某候选实现坏了 → **回 ③** 重写该候选
- 决策表判定无可挽回 → **停止**

### ⑥A Codex sol ultra：基于证据生成并比较方案

**⑥A 不是"只挑刺"。** Sol 必须从用户原始意图、候选实现和原始实验数据出发，
独立提出、改造或合成可实施方案，并**按以下顺序**输出：

1. **证据账本**：逐候选列出已核验的数据、噪声与不确定性、失败记录、硬约束是否满足，
   以及哪些结论没有被数据支持。
2. **方案集**：输出 1–3 个仍受证据支持的方案；每个方案用**相同字段**说明实现轮廓、
   支持证据、成立条件、已知弱点、失败条件，以及什么新数据会使它退出候选。
3. **条件化判断**：完成对称比较后，可以给出"在条件 X 成立时优先方案 A"的**有条件首选**，
   也可以明确写"现有证据不足以排序"。
   **不得使用"最终方案""默认答案""应直接采用"等无条件定案措辞。**

**方案数量由证据决定，不得为满足格式制造假选择。** 若只有一个方案仍受支持，
应明确写"当前只有一个可晋级方案"，同时列出最强替代及其被数据否决的具体原因；
该替代须标为"已否决"，不得伪装成仍可竞争的方案。若没有方案得到足够支持，
应输出"无可晋级方案"，并指出应停止还是返回 ①、③ 或 ⑤ 补充证据。

Sol 可以提出包含新机制的方案，但必须逐项标注"已测""部分已测"或"未测"。
**含未测关键机制的方案只能列为未验证假设**，且**必须先回 ① 把它补进预注册候选表与决策表
（并更新 journal），再走 ③–⑤**——与 ② 和 ⑦B 的新候选处理**同一语义**。
看过首轮结果后才产生的方案若跳过预注册直接进 ③，就脱离了事前决策表的约束。
**不得直接进入 ⑧。**

**⑥A 的条件化判断属 advisory，不拥有定案权。** ⑦A 仍须亲自核对原始数据，⑦C 仍须写出自己的选择依据；
**仅复述 ⑥A 的首选不满足 `[OWNERSHIP]`。**

**喂什么**：全部 `runs/` 原始数据 + `EXPERIMENTS.csv` + N 份实现关键代码 + N 份原型快审意见
+ **用户原话** + L0 的观察（须标注"以下是我的解读，可被数据推翻"）。走 stdin，不用 argv。

### ⑥B 独立实验证据审阅（advisory，与 ⑥A 并行且互盲）

> **定名**：它只有只读工具、**做不了重算**。若叫"复核"会让**第二份叙述被误当成第二份实证**。

- 全新 Claude 上下文，**只读**（`Read`/`Grep`/`Glob`，不给 `Write`/`Edit`/`Bash`）
- **收**：用户原话、候选/run 清单、测量代码与黄金样例、原始数据、哈希、候选代码、实验配置
- **不收**：⑥A 的报告、L0 的观察 / 偏好 / 草拟结论
- **干**：静态审阅测量有效性、候选间可比性、数据是否支持结论；从数据独立重建可行方案与反证
- **能力边界（须写进简报，并要求写进报告）**：**不复现、不重算、不运行黄金样例**；
  报告须列出**实际读取了哪些文件**与**哪些项未核验**
- **不定案、不充当 Plan-Gate、不得称为 L2**

**独立性的准确描述（四句都要写清，不得简写为"独立第三方"）**：

- 相对 ⑥A 的 Sol —— **不同模型家族且上下文互盲**
- 相对 L0 当前判断 —— **全新上下文**，未接触 L0 偏好或草稿
- 相对 L0 的模型家族 —— **不独立**（L0 为 Claude 时二者同族）
- 相对 ① 预先定义的候选 / 指标 / 测量材料 —— **不独立**，消除不了共同输入框架造成的盲点

> ⚠️ **"既审 ⑥A 的方案、又与 ⑥A 互盲"无法同时成立。** 本流程选择让 ⑥B **不看 ⑥A 报告、
> 独立重建结论**；两份报告的冲突由 ⑦A 整理成分歧清单（并成为 ⑦B interview 的入口），交 ⑧ 逐条回应。
> 若哪天改成让它读 ⑥A 报告，它只能称为"⑥A 报告反证审"，**不得再声称互盲**。

### ⑦A · L0 核数据 + 形成分歧清单

- **L0 必须亲自核对原始数据**：⑥A/⑥B 报告是二手（`[EVIDENCE-FIRST]`）。一手材料按候选状态分：
  - 跑成的 → `metrics.csv` / `EXPERIMENTS.csv`
  - **`status: failed` 的 → `config.json` + `run.log`**（失败候选没有指标行是正常的）
  - **被判无效的 → L0 亲自核过的缺陷位置/工件/可复现命令 + `config.json`**
    （④ 快审记录只是定位线索，不是一手证据）
  **不得照抄推荐；也不得因某候选没有指标行就把它排除在核对之外。**
- 对照两份互盲报告，**形成分歧清单**（供 ⑦B 与 ⑧ 逐条回应）

### ⑦B · 强制 `interview-me` 意图对齐（无条件，只固化偏好、不作技术选择）

- **触发**：⑦A 完成即触发，**无条件**——不看清单条目多少、不看 L0 主观感觉"有没有歧义"。
  主观触发阀必被拿来自我豁免（"我以为自己听懂了"是最典型的漏网口），只用机械项才守得住。
- **前提·必须有活跃用户**：`interview-me` 是交互式 skill，禁在 subagent / CI / loop 等非交互上下文调用。
  实证流由 L0 定案，通常有活跃用户；但**长实验结束时用户可能已离开** —— 若发起 ⑦B 时无活跃用户，
  **暂停,待用户回来再继续**，不得替用户走完 interview。
  若你是 L1 子代理路过读到本节，**你不该跑 ⑦B**，回 L0。
- **形态**：invoke `agent-skills:interview-me` skill，把分歧清单作为完整上下文喂入，
  一问一答直到 ~95% 意图对齐；**鼓励发散多个可行方向，一起把候选/权衡/偏好/边界摆到台面上**。
- **skill 契约覆盖**：`interview-me` 默认 "When NOT" 禁在"无歧义 / 机械操作 / 已有 ≥95% 把握"
  时调用。**本节明写覆盖**：⑦B 无条件触发（覆盖默认时点门槛）；实证流因已有分歧清单，
  额外要求产出附一个"处置意向"（见下）。此处不让 `interview-me` 出技术方案——技术选择归 ⑦C。
- **产出**（两块，缺一不可）：
  - 一份**用户确认的意图/偏好/非目标**（`interview-me` 的默认输出，属"意图陈述"）
  - 一个**处置意向**（五种之一，L0 与用户共同拟定；具体分支执行在 ⑦C）：
    - **选其一** —— 从分歧清单挑一个候选
    - **合成** —— 融合多个候选
    - **全部不选后新做** —— 分歧清单里的都不合意图，需要新候选
    - **停止** —— 数据/意图都不支持任何候选，本任务应暂停或回退
    - **补测** —— 现有证据不足以定，必须回 ①/③/⑤ 补跑再来
- **收敛失败的处置**：若 `interview-me` 数轮不收敛（按其 skill 内规"三轮以上信心不提升"），
  **暂停并报告 blocker**——L0 不得静默替用户决定，也不得为"跑通流程"硬造一个赢家。
- **与 Plan-Gate 分工**：**⑦B 主责用户意图对齐**（哪条路才是你要的、有没有更好没想到的、
  有没有你觉得都不该选）；**⑧ Plan-Gate 主责方案质量**（需求误解 / 过度设计 / 更优解 / 拆解质量）。
  兜底仍归 Plan-Gate，但 ⑦B 挪走"用户偏好"类分歧，让 Plan-Gate 少来回。
- **例外**：只沿用 CLAUDE.md §9 已豁免范围——不添新例外。

### ⑦C · 按 ⑦B 处置意向分支执行（唯一决定谁进 ⑧）

**⑦C 是分支控制流，不是"再选一次"**。按 ⑦B 定下的处置意向执行对应出口：

| ⑦B 处置意向 | ⑦C 出口 | 是否进 ⑧ Plan-Gate |
|---|---|---|
| **选其一** | 若选中的候选与 ⑦A 数据一致 → 写 spec/plan（含"为什么选它" + "什么样的数据会让我改选"）；**若不一致 → 回 ⑦B**（下方） | ✅ 或回边 |
| **合成** | 若合成机制**已测** → 写 spec/plan；**含未测关键机制** → 走"全部不选后新做"出口（下一行）；若合成候选与数据不一致 → 回 ⑦B | 情况而定 |
| **全部不选后新做** | 回 ①：把新候选补进预注册候选表 + 决策表 + 更新 journal → 回 ③–⑤ 跑；⚠️ **本次不进 ⑧**，回边完成再来 | ❌ 本次不进 |
| **停止** | 记 journal 收尾（保留分歧清单、⑥A/⑥B 报告、⑦B 意图记录作为已知遗留），**结束本任务**；**不写 spec/plan、不进 ⑧** | ❌ 完全不进 |
| **补测** | 依 ⑦A 分歧清单显示的缺口，回 ①/③/⑤ 中相应节点补跑；⚠️ **本次不进 ⑧**，补齐再来 | ❌ 本次不进 |
| **意向与数据不一致（回边）** | ⑦C 不得替用户覆盖或卡死。把冲突证据反馈给用户，**回 ⑦B 重新过一遍 interview** 重新确定处置意向（可能选其他、可能补测、可能停止） | ❌ 本轮不进 |

**⑦C 的 L0 职责**：核对 ⑦B 处置意向是否与 ⑦A 数据一致（用户拍板归用户，**数据不支持时不得静默覆盖、也不得卡死**——走回边行）；按分支表选出口；写产出（spec/plan 或 journal 收尾条）。

**不允许"停止/补测/新做/回边"绕道进 ⑧**——写生产 spec/plan 就是"承诺要建这个"，
处置意向不是"选其一/合成"却硬进 Gate 等于对用户扯谎。

### ⑧ Plan-Gate（硬门槛）

形态同 `~/.claude/ops/plan-gate.md`：1 个 `gpt-5.6-sol` + `ultra` + `-s read-only`，
四维单审，spec+plan 同审；**三闸 + 四维标题校验由 L0 亲自做**。

**本流程专有的三条附加要求**：

- 喂**全部候选（含落选）的原始数据**，并明令
  「**以数据为准，不采信 spec 里的叙述性论断**——凡 spec 说『实测表明 X』，请回 metrics 自己核」
- 喂 ⑦A 的**分歧清单** + ⑦B interview 的**收敛记录**（⑥A 与 ⑥B 报告的冲突处 + 与用户的意图对齐过程），要求**逐条回应**
- 提供候选/run 清单、文件哈希与覆盖表，**要求输出逐候选核验状态**
  （走 stdin 只解决 `ARG_MAX`，不解决"是否真读完"）

简报**不提**方案源自另一次 sol 调用——身份信息只带来锚定，不带来判断力。

> ### ⚠️ ⑧ 自己提出新机制时的回边（**最隐蔽的一条绕过路径**）
>
> ⑧ 的四维里有"更优解 / 隐藏假设"，**它完全可能提出一个没被实测过的新机制**。
> 若不写死回边，路径是：**⑧ 提新机制 → L0 采纳写进 spec → 重过 ⑧ → 直接进 ⑨**。
> 结果是：**一个从未预注册、从未做原型、从未跑过数据的机制成了交付依据**——
> 实证流在自己的最后一道关卡上退回了"对文本猜"。同理适用于 `[FABLE-ADVISOR]` 的建议。
>
> **硬规则**：在 ⑧ 阶段采纳**任何未测的关键机制、新候选或测量口径变更**，
> **必须回 ① 重新预注册 → 重走 ③–⑦ → 再过 ⑧**。
> 只有"不涉及未测机制的措辞澄清、拆解调整、验收标准细化"才允许就地改 spec 后重过 ⑧。
> **判据**：这条改动会不会让最终实现里出现**数据没覆盖过的行为**？会 → 回 ①。

> ⚠️ **`ops/plan-gate.md` 的三闸 + 四维标题检查验不了上面这三条**（它只验非空、哨兵、
> 正文、四维标题）。模型即使完全漏掉落选候选或分歧清单，也能通过硬门槛——这是 fail-open。
> **补一道 L0 亲自做的覆盖核验，缺任一项即判本轮 Gate 无效、重发**：
> 1. 输出中**每个候选名**（含落选）都有核验状态，**且状态必须是下列之一并附证据指针**：
>    - **`已核验`** —— 证据指针 = `runs/<候选>/metrics.csv` 的具体指标行 + hash
>    - **`已核验(failed)`** —— 该候选 `status: failed`（OOM/超时/不收敛）。
>      证据指针 = `config.json` + `run.log` + 候选 hash。**没有指标行是正常的，不得因此判无效，
>      更不得捏造指标行**
>    - **`已核验(invalid)`** —— 该候选被判为无效（指标算错/数据泄漏）。
>      ⚠️ **④ 的快审报告是二手证据（`[EVIDENCE-FIRST]`），单凭它不足以淘汰候选**——
>      若 ④ 误报，一个本可胜出的候选就被静默淘汰了。
>      证据指针 = **L0 亲自核过的代码位置 / 原始工件 / 可复现的失败命令与输出** + `config.json`；
>      ④ 报告只用于**定位**"该去看哪里"
>
>    **`未核验` / `未读取` / `无法判断` 一律判本轮 Gate 无效**；
>    **`缺材料` 仅在「本应存在却缺失」时才判无效**（如 `status: done` 却没有 `metrics.csv`）
> 2. **分歧清单每一条**都有实质回应；**`无法回应` / 跳过 同样判无效**
> 3. 二者缺失时**不得**以"审查没提就是没问题"放行
>
> ⚠️ 只查"候选名出现过"是**形式覆盖**，拦不住「候选A：未核验」这种字面满足——
> 必须查**状态值**与**证据指针**（L3 实测指出的 fail-open）。
> 核验结果逐项写进 `$GATE/disposition.md`。

### ⑨ 生产化：六步协议（**有顺序，不是并列条件**）

赢家原型**可以晋级，无须从头重写**，但必须按顺序走完：

1. **锁定**行为/验收契约、容差、测量流程 ——
   ⚠️ **这三样都必须已在 ⑦C 的 spec 里写明并经 ⑧ 审过**；⑨ **只负责读取并锁定已审版本，
   不得在此首次产生或修改**。契约源自需求与指标契约，**不得从赢家实现反推**。
   **任何补充或改动 → 回 ⑦C 改 spec 并重过 ⑧**，不得就地新增验收标准
   （否则等于绕开 Gate 追加了实现要求）
2. **建立并验证验收测试** —— 至少让一个已知错误版本 / 落选候选 / 故障注入**真实失败**
   （防无断言、错 fixture、名不符实 —— 本机有前科）
3. **按 TDD 整理、加固**最终代码
4. **在候选最终 hash 上**跑验收测试 + 实证回归
5. **对同一 hash** 跑 L2、L3 终检
6. **任一实质修改使第 4、5 步的证据失效** —— **必须重跑第 4–5 步**

> **为什么写成有序协议而不是"同时满足的前置条件"**：后者会形成循环依赖
> （L2/L3 要对应最终 hash，而回归又要在 L2/L3 之前），
> **后果可实际触发**：审查 hash A、修复后交付 hash B，终检静默失效。

**回归失败的分流**：

- 只是**实现缺陷** → 留在 ⑨ 修复并重跑第 4–5 步
- **实验推翻了机制选择或 spec** → 才回 ⑦，并重新过 ⑧

**TDD 的准确说法**：原型阶段豁免 TDD；决定晋级后先建立契约驱动且经有效性验证的测试，
此后的整理、加固与修改按 TDD 执行。
**不得声称原型本身"补做后就变成了 TDD"。**

之后照常 `[PR-GATE]`。

## 3. 硬门槛不变

`[PR-GATE]`、审查者只读、`[DELEGATION-BAND]` 行数带全部照常。

本流程改的是"**怎么做决策**"，不是"**成品怎么验**"。

L3 改完不重审、PR head 变化不重审、guard 急停无约束、Gate 适用范围不一致）——
**它们全是在成品里才显形的**，四轮 Plan-Gate 一个都没发现。

## 4. 模型独立性与已知盲点

本流程提供的是**有限的流程独立性，不是完整的模型家族独立性**。
⑥A 与 ⑧ 使用互不继承上下文的 Codex 调用，可以减少共享会话记忆和直接自我背书；
⑥B 使用全新的 Claude 上下文并与 ⑥A 互盲，可以从另一模型家族独立解释实验材料。
但 **L0 与 ⑥B 同属 Claude 家族**（此为 L0 属 Claude 时的描述；若 L0 换成 Codex 家族，
独立关系需重新描述，本节前提不再成立），**⑥A 与 ⑧ 同属 Codex 家族**；
本机没有第三个模型家族，因此**不得把任何一步称为完全独立的第三方裁决，
也不得声称同家族盲点已经消除**。

原始数据、冻结测量流程、黄金样例、文件哈希、逐候选覆盖记录、最终复验和强制反论证
能够提高可追溯性，并帮助发现算错、选择性引用、结果不可复现或叙述与数据不符的问题。

**它们治不了以下问题**：共享测量代码和黄金样例一起出错；目标或指标本身选错；
遗漏了关键候选；实验环境没有覆盖真实使用条件；用户意图被误解；
以及同一模型家族在需求、实验设计、架构或 YAGNI 判断上共享先验。
**要求"唱反调"只是输出约束，不会自动创造新的先验或独立证据；
提供全部数据也不等于数据已经被完整读取或证明正确。**

因此，本流程的价值不是证明方案必然正确，而是**把原本依赖文本直觉的争论
变成可运行、可复核、可被新数据推翻的决策过程**。
独立上下文、Claude/Codex 交替复核和非生成式实验凭证能够降低部分锚定与漏检概率，
并让错误更容易定位。

**若两份报告冲突、测量有效性受质疑，或关键结论仍只靠共同先验支撑，
不得按多数票或模型身份放行**；应返回测量、补跑实验，或由 L0 请求用户裁定。
**Plan-Gate 通过只表示在已审材料和现有证据中没有发现未解决的阻断项，
不表示获得了全局正确性证明。**

## 5. 成本与已知边界

- **wall-clock 未必更长**：③④ 与 ⑥A/⑥B 都是并行，代价主要在 token 而非时间
- **token 确实更贵**：N 份实现 + N 轮原型快审 + ⑥A + ⑥B + ⑧。
  换来的是**决策建立在数据上**，而不是两个模型对着文本互相说服
- **不适用**：产出本身就是最终物的任务（规范文本、文档、架构拉定）→ 走标准流水线
- **残余盲区**：② 的设计审只问两个问题，不保证穷尽；
  若 N 个候选全都错了，数据只能告诉你"这几个都不行"，不会指出第 N+1 个
- **fable5 不参与本流程**：它是 `[FABLE-ADVISOR]` 的 break-glass 只读架构顾问，
  仅在 Plan-Gate 阶段架构僵局时按窄触发启用，**不作为常规评审步骤**
