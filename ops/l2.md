# L2 跨家族快审（唯一事实源，从 CLAUDE.md §4 外置）

> **配置根**：若本规则体系不在 `~/.claude`，按 CLAUDE.md 所在目录解析下文路径。

## §0 读不到本文件时怎么办（控制流，先看这条）

主文各处指针写的是"跑 L2 前必须先 Read 本文件；读不到则不得发起 L2"。
**读不到的处置（与 fail-不阻断语义一致，不制造死锁）**：

1. **不得凭记忆发起 L2**——凭记忆拼的参数/语义大概率不符 §3 四判据，属无效发起，反而污染证据；
2. **不阻断流水线**：按 §3 的 fail-不阻断语义处理，即**记录"L2 未生效"后照常进 L3 终检**；
3. **固定留痕句式**：「`ops/l2.md` 不可读，L2 未发起；L3 照常全审」，并提醒用户修复该文件。

注意区分：**L2 本身是减负漏斗、非硬门槛**，故读不到只影响 L2 这一步；
`[PLAN-GATE]`、`[ENGINE-ASSIGNMENT]` 的 L3 终检、`[PR-GATE]` 都是硬门槛，**不因本文件不可读而豁免**。

## §1 定位与触发范围

**定位**：落地后、L3 终检前的**便宜跨家族粗筛**——它是 L3 的减负前哨，
**是减负漏斗、非硬门槛**（fail 不阻断语义见 §3）。
"交付变更集"「审查对象 / 计量对象 / 计量单位」「L0 自写同等适用」「判不准从严」等定义
**见 `~/.claude/ops/line-count.md`，此处不重述**；跑 L2 前若涉及这些判定，先 Read 该文件。

- **触发**：**所有落地的代码变更都过**（范围与作者归属见 `~/.claude/ops/line-count.md`；哪怕极小改动——用户拍板的全量策略，换吞吐换彻底）。
- **范围**：单元级 bug / 局部改进 / 可读性；**不裁决架构**，仅标记"架构嫌疑"升级。

## §2 跨家族选档矩阵

  - **L2 跨家族快审（落地后、终检前的便宜粗筛）**用**跨家族档**（Codex 侧 `max`）：L1 是 Claude(Sonnet/Haiku) 时用 **Codex `gpt-5.6-luna`**（跨到 Codex 家族）；L1 是 Codex(luna) 时改用 **Claude(Sonnet 默认/Haiku)**（跨回 Claude 家族）。**关键约束（选档要求，非结果保证）：必须为每个作者家族的产出【发起】一轮异家族的完整变更集审查**——单一作者时即"审查方跨出产出者家族"；**混合作者时两家族各发起一轮完整集审查**（见 `~/.claude/ops/line-count.md` 兜底原则）。**绝不以同家族审查【代替】异家族审查**（同家族 = 异构粗筛破功）。

## §3 有效发起四判据 + fail-不阻断语义 + 固定记录句式

- **什么算「有效发起」**（**四项齐备，缺一即不算发起、须重发**）：
  1. 审查者家族**跨出了产出者家族**；
  2. 输入是**完整变更集**（非片段、非空简报）；
  3. **调用参数与任务语义均符合本规则规定**——指定的审查模型档、推理档（Codex 侧 `max`）、**只读权限**（Codex `-s read-only`；Claude `Agent` 限只读工具集——依`[GRANT-PERMISSIONS]` 的审查关卡例外）、且**该次调用的任务确实是审这份变更集**。**凡参数或语义不符者，无论是否报错、哪怕成功返回，一律不算有效发起**（用错模型档却跑通、或跑的是无关任务，都不算）；
  4. 有**可查的调用证据**——**Codex 侧**＝命令 + `-o` 输出路径 + **退出码**（输出文件失败时可能不存在，故退出码不可省）；**Claude `Agent` 侧**＝该 subagent 的调用记录/返回内容指针（无 shell 命令亦可，但须能指出"哪一次调用、审了什么"）。≤400 行且未建档时，证据记在收口汇报里即可。
  **不要求成功产出**——这才不破坏 fail-不阻断语义；但"不要求成功"≠"随便发一个就算"。
- 有效发起后仍失败 / 空输出 → 依本节 fail-不阻断语义放行进 L3，但收口须按固定格式明记：**「面向 `<作者家族>` 产出的 `<审查者家族>` L2 未生效；L3 照常全审」**（混合作者时逐条记，避免"某家族"指代不清）。**L2 是唯一允许 Claude 审【落地后完整变更集】的一层**（frontier 审查仍只用 Codex gpt-5.6-sol）；L2 始终是便宜档，不升 gpt-5.6-sol（那是 L3 的活），二者之间是成本/强度梯度。
  ⚠️ **两个窄例外（实证流专有，2026-08-07 加）**：`ops/empirical-flow.md` 的 **④** 与 **⑥B**（⑥B 由 Claude 承担；④ 的家族随原型作者而定，见下）**都不是 L2**，且**审查对象完全不同，写简报时不得混淆**：
  - **④ 原型快审**——审**单个候选原型及其测量接口**，只查会污染数据的局部错误；生命周期止于原型阶段。
    ⚠️ **审查者家族相对【该原型作者】而定**：作者是 Codex → Claude 审；**作者是 Sonnet/Haiku → 反过来由 Codex 审**。不是固定由 Claude 承担
  - **⑥B 独立实验证据审阅**——**接收全部候选、全部 run、原始数据与配置，做跨候选的全局比较并独立重建结论**。**若按"单候选快审"写它的简报，就会把全局比较缩水，⑦ 也拿不到真正的横向分歧清单**
  二者**都是 advisory、都不裁决方案、都工具层只读**。**不得归入 L2，也不得因本节声明而跳过。** 硬门槛级独立审查（⑧ Plan-Gate 与 L3）仍铁打地只用 Codex。

- **"跨家族"约束是对 L2 选档的硬要求，不是对结果的保证**：**有效发起后**（判据见本节「什么算有效发起」）L2 失败/空输出不拦路（fail 不阻断、非硬门槛），但 L0 主循环收口须按固定格式明记「面向 `<作者家族>` 产出的 `<审查者家族>` L2 未生效；L3 照常全审」，连续失败提醒用户；**绝不以 L2 通过为由跳 L3 终检（`[ENGINE-ASSIGNMENT]` / §2.5）或 Plan-Gate（`[PLAN-GATE]`）**。即 L1=Codex 时若 Claude L2 挂了，允许直接进 L3（best-effort），不强求跨家族快审必须成功。

## §4 调用（bin/l2 首选）

   ▶ **别手拼命令——直接跑 `~/.claude/bin/l2 --author <claude|codex|mixed>`**（`--dry-run` 先看要跑什么）。它按作者家族自动选跨家族档、拼好 `-m`/`effort`/`-s read-only`/`-o`、组织完整变更集，**手工 8 步压到 2 步**（只剩"跑一条命令"+"分诊"）。手拼易漏 `-o`（那是有效发起的证据要件）或选错家族导致同家族自审。

**手工兜底（`bin/l2` 不可用时）**——参数不得改档：

- **Codex 审**（产出者是 Claude 时）：
  `codex exec -m gpt-5.6-luna -c model_reasoning_effort="max" -s read-only -o <留痕路径> ...`
- **Claude 审**（产出者是 Codex 时）：`Agent` + `model: "sonnet"`/`"haiku"`，
  工具集限只读（`Read`/`Grep`/`Glob`，不给 `Write`/`Edit`/`Bash`）；
  **勿用与 L3 同形的裸 `review` 命令以免混淆**。

## §5 输出契约（must-fix / nit）与 must-fix 修完复审

- **输出契约**：分 `must-fix`（bug/正确性）与 `nit`（优美度/建议）两档，每条含文件:行定位——避免一堆建议把分诊成本反推给 L0 主循环。
- **只管单元级**：bug、局部改进、可读性 / 优美度；**不裁决架构**（疑似牵涉架构只标记"架构嫌疑"升级 L3 / L0 主循环）。
- **L0 分诊**：优先处理 must-fix，派回 L1 修；nit 自行取舍；误报留痕跳过。
  **修完要对修复 diff 再发起一轮 L2**（修复本身也是新变更），再进终检。
